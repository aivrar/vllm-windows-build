## Port changes

- Carry the native build, packaging, process, socket, weight-loading and Rust adaptations into 0.29.0, including the relocated server entry points.
- Report compiled CUTLASS FP8 availability accurately. Windows automatic selection prefers Marlin over the Torch fallback when native CUTLASS is unavailable. NVFP4 retains its compiled-capability check and Marlin fallback.
- Provide the partition metadata required by Marlin for compressed-tensors FP8 LM heads, including padded vocabularies.
- Adapt the six local KV compression formats to the new Triton attention cache layout. Preserve the four upstream TurboQuant formats.
- Preserve upstream shared-cache layout and synchronization changes while carrying Windows mmap, native copy and filesystem behavior. Delete cache files only on proven short reads, preserving files on other I/O errors.
- Fail configuration when a vendor patch neither applies nor is already applied.
- Copy and rewrite FlashAttention CuTe Python files for local Windows vendor checkouts, avoiding upstream's development-only symlink path in release wheels.
- Expose `--linear-backend` through the launcher. Reject unsupported legacy `--num-scheduler-steps` values before loading a model.

## Validation record

- Existing-release baseline: 30 focused tests and wheel integrity/payload checks passed before porting.
- Changed launcher configuration: four tests passed; unsupported scheduler-step values produce an actionable argument error.
- Shared-cache regressions: six targeted checks passed, covering Windows-safe paths, layout namespaces, shared-memory visibility, cleanup and failure handling.
- Exported v11 source patch: `git apply --check` passed against the clean upstream 0.29.0 snapshot.
- Optimized Rust frontend: build passed; the executable reports `vllm-rs 0.29.0`.
- Optimized Rust parser extension: build passed and `_rust_tool_parser.pyd` was copied into the package.
- CUDA native targets: all 198 build steps completed and the native artifacts were copied into the package. Optimized Rust artifacts are reused for assembly.
- Wheel assembly and integrity/payload validation passed, including CRCs, RECORD hashes, metadata and all 51 rewritten CuTe Python files.
- Installed-wheel version, location and all required module imports passed. Both packaged Rust artifacts match their optimized release outputs byte for byte.
- RTX 3090 FP8 regression: automatic Marlin selection passed for a padded LM head, with and without bias; relative L2 error against the reference was 0.223% and 0.276%. Capability metadata was mocked as SM120 while the kernels executed on the 3090; this does not validate Blackwell execution.
- All six local cache formats passed actual backend write/decode checks for the new layout, block remapping and ignored slots. These are cache-operation checks, not full-model quality evaluations.
- Updated repository release contract: 15 checks passed.
- Real-model serving: Qwen3.5-9B GPTQ on RTX 3090, V2 runner, compilation and CUDA graphs enabled. Ordinary and streaming chat both returned HTTP 200 and the expected answer, `4`.
- CPU-LRU offload: identical generated token IDs after clearing GPU prefix cache, with 1,056 cached tokens restored from a 1,452-token prompt.
- Filesystem-ARC offload with 256 MiB CPU staging: identical token IDs and 1,056 reused tokens after GPU reset and additional distinct prompts. A fresh process then reused 1,056 filesystem-cache tokens on its first request with identical output, proving disk persistence independently of RAM residency.
- The initial 64 MiB filesystem test could allocate only three staging blocks and restored zero tokens for this hybrid model; increasing staging to 256 MiB (15 blocks) resolved the capacity shortfall. This is not a claim that arbitrarily small staging caches are usable.

Validation was targeted: CPU-LRU and filesystem-ARC covered the shared Windows cache paths and both policies. Other policy combinations, all model families and Blackwell hardware were not exhaustively tested. The test processes exited and released the RTX 3090.

## Build notes

The build uses an isolated checkout and virtual environment. Load the Visual Studio 2022 x64 build environment, then put the virtual environment, CUDA 13.0, Git and Rust tools on a short `PATH`. Git for Windows' `usr/bin` directory supplies `patch.exe`, now required by upstream's Torch-header patch step. Pass vendor source paths to CMake using forward slashes; raw Windows backslashes in `VLLM_FLASH_ATTN_SRC_DIR` cause an invalid escape in FetchContent.

Set `TORCH_CUDA_ARCH_LIST=7.5;8.6;8.9;12.0`, `VLLM_TARGET_DEVICE=cuda`, `CMAKE_BUILD_TYPE=Release` and `SETUPTOOLS_SCM_PRETEND_VERSION=0.29.0`. This build uses `MAX_JOBS=8`. Set `OPENSSL_SRC_PERL` to a complete Perl installation and `PROTOC` to the protobuf compiler for the Rust frontend.

First build and install both optimized Rust artifacts with `.venv\Scripts\python.exe tools\build_rust.py --release`, with `VLLM_RS_BUILD_VERSION=0.29.0`. Then compile CUDA with `.venv\Scripts\python.exe setup.py build_ext --inplace -v`. The Rust artifacts must exist when `setup.py` starts so its build command reuses them instead of initiating a debug Rust build afterward. The new SITU activation kernel needs its ROCm preprocessor guard outside the dispatch macro arguments for MSVC; the port preserves both kernel branches.

For assembly, set `VLLM_USE_LOCAL_PRECOMPILED=1`, `VLLM_SKIP_PRECOMPILED_VERSION_SUFFIX=1` and `VLLM_VERSION_OVERRIDE=0.29.0`, then run `uv build --wheel --no-build-isolation` using the build environment. Validate the archive before installing that exact wheel outside the source tree. Source-tree imports alone are not installed-wheel validation.

## Tester scope

Blackwell-native FP4 is not claimed. The target is the updated Windows runtime with the working Marlin fallback for the mixed NVFP4/FP8 checkpoint from issue #16. Local RTX 3090 results cannot establish SM120 execution.

Use a separate installation and a fresh filesystem-cache directory for the candidate. Report the exact model revision, driver and package versions, selected backend, startup/request result and any traceback. Keep cold-start/JIT timing separate from warmed performance and redact API keys from logs.
