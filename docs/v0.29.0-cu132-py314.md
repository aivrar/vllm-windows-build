# vLLM 0.29.0 — Python 3.14 / CUDA 13.2 prerelease

Tag: `v0.29.0-win-cu132-py314-rc1`. This is a separate runtime variant of
0.29.0, alongside the Python 3.13 / CUDA 13.0 prerelease. Stable/Latest remains
0.27.1. It addresses [issue #17](https://github.com/aivrar/vllm-windows-build/issues/17).

## Install

Download **Source code (zip)** from the
[release page](https://github.com/aivrar/vllm-windows-build/releases/tag/v0.29.0-win-cu132-py314-rc1),
extract into a **new directory**, and run `install.bat`, then `launch.bat`.
The source ZIP contains the matching portable installer; no compilation is
needed. Do not run the stable or cu130 installer against this wheel.
Use a fresh filesystem KV-cache directory when testing this installation.

The installer downloads and verifies Python 3.14.2, its matching headers/libs,
the vLLM wheel and the unchanged Multi-TurboQuant 0.1.0 companion. Dependencies
are constrained to the tested environment in `constraints-cu132-py314.txt`.
It uses Torch 2.13.0+cu132, torchvision 0.28.0+cu132, torchcodec 0.16.0+cu132,
and triton-windows 3.7.1.post27. A compatible NVIDIA driver is required;
the local tests used driver 596.36. The installer does not install a driver
or a system CUDA toolkit.

**TorchAudio uses the CPU wheel, version 2.11.0 from PyPI** (runtime identifies
itself as `2.11.0+cpu`). No matching cu132 wheel was available. Import and CPU
resampling passed; GPU audio processing and audio-model serving were not
validated. vLLM model inference still uses CUDA.

## Artifact and validation

- `vllm-0.29.0-cp314-cp314-win_amd64.whl`, 242,283,093 bytes.
- SHA256: `a3e9a18b671673771ad233ea75c3e14f4d598bb1468d31565bec07e0111f96bc`.
- Exact installed wheel passed archive/RECORD/native-payload checks, required
  imports, optimized Rust payload hashes and dependency compatibility checks.
- RTX 3090: Qwen3.5-9B GPTQ ordinary and streaming chat returned the expected
  answer with V2 runner, compilation and CUDA graphs enabled.
- Padded FP8 LM-head Marlin checks passed with and without bias. All six
  local Multi-TurboQuant formats passed write/decode checks.
- Filesystem ARC restored 1,056 cached tokens with identical generated IDs,
  including the first request after a fresh process restart. This exercised
  FlashAttention and CPU staging as well as disk persistence.

The Windows features and issue #16 fallback fixes from the
[cu130 update](v0.29.0-release-notes.md) are retained: native CUDA/MoE modules,
FlashAttention, Rust frontend/parser, launcher controls, six local and four
upstream KV formats, and opt-in CPU/filesystem LRU/ARC offload.
The new variant does not establish native Blackwell FP4 support; existing
SM120 CUTLASS FP8/NVFP4 exclusions remain. Blackwell execution needs a tester.
No speed improvement over Python 3.13/cu130 is claimed. First cold imports
were unusually slow locally in metadata and bytecode-cache work; subsequent
starts were normal. This has not been established as a Python 3.14 regression.

## Exact source and build changes

Upstream vLLM v0.29.0: `98dff2a81d747d1dba01a47f939f48c3526d4206`.
Apply the unchanged `vllm-windows-v11.patch`, then `vllm-cu132-topk.patch`
in the vLLM checkout. The latter replaces GCC-specific `__FLT_MAX__` with
standard `FLT_MAX` and includes `<cfloat>` for CUDA 13.2/MSVC.

```bat
git checkout 98dff2a81d747d1dba01a47f939f48c3526d4206
git apply --check ..\vllm-windows-v11.patch
git apply ..\vllm-windows-v11.patch
git apply --check ..\vllm-cu132-topk.patch
git apply ..\vllm-cu132-topk.patch
```

Before configuring, check out FlashAttention at
`06bdd47c0d0383daf6a2ff0c418faff9c6da16e5`, initialize its CUTLASS submodule
(`62750a2b75c802660e4894434dc55e839f322277`), and apply
`flash-attn-python314.patch` **inside the FlashAttention checkout**. This adds
3.14 to its CMake allowlist. Set `VLLM_FLASH_ATTN_SRC_DIR` to that checkout;
this extra patch is not automatically applied by v11. Use forward slashes in
CMake vendor paths and include Git's `usr/bin` on PATH for `patch.exe`.

Other build pins: CUTLASS v4.4.2
`da5e086dab31d63815acafdac9a9c5893b1c69e2`; Triton kernels
`0add68262ab0a2e33b84524346cb27cbb2787356`; MSVC 19.43.34810;
CUDA Toolkit 13.2 Update 2 / nvcc 13.2.86; Python 3.14.2;
`TORCH_CUDA_ARCH_LIST=7.5;8.6;8.9;12.0` with existing kernel exclusions.
See the [base port build record](v0.29.0-build-candidate.md) for the inherited
workflow; its Python/CUDA pins must be replaced with this variant's pins.
The historical root `build.bat` is not this build's recipe.

All CUDA/C++ extensions were rebuilt. Identical-source optimized Rust
executable and `abi3-py38` parser were reused from cu130; Python 3.14 imports
and packaged hashes passed. For a fresh build, finish release-mode Rust
artifacts before starting `setup.py build_ext` to prevent a debug rebuild.
